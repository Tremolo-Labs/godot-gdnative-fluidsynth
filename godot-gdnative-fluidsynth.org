godot-gdnative-fluidsynth
=========================

Godot gdnative fluidsynth library to allow playing music using fluidsynth. Provides some primitives like ~AudioStreamMidiTrack~ and ~EventStreamMidiTrack~.

## Contents
,* godot-cpp as a submodule (`godot-cpp/`)
,* GitHub Issues template (`.github/ISSUE_TEMPLATE.yml`)
,* GitHub CI/CD workflows to publish your library packages when creating a release (`.github/workflows/builds.yml`)
,* preconfigured source files for C++ development of the GDExtension (`src/`)
,* setup to automatically generate `.xml` files in a `doc_classes/` directory to be parsed by Godot as [GDExtension built-in documentation](https://docs.godotengine.org/en/stable/tutorials/scripting/gdextension/gdextension_docs_system.html)


### Configuring an IDE
You can develop your own extension with any text editor and by invoking scons on the command line, but if you want to work with an IDE (Integrated Development Environment), you can use a compilation database file called `compile_commands.json`. Most IDEs should automatically identify this file, and self-configure appropriately.
To generate the database file, you can run one of the following commands in the project root directory:
```shell
# Generate compile_commands.json while compiling
scons compiledb=yes

# Generate compile_commands.json without compiling
scons compiledb=yes compile_commands.json
```

## Usage - Actions

This repository comes with a GitHub action that builds the GDExtension for cross-platform use. It triggers automatically for each pushed change. You can find and edit it in [builds.yml](.github/workflows/builds.yml).
After a workflow run is complete, you can find the file `godot-cpp-template.zip` on the `Actions` tab on GitHub.

*** Project Overview

Godot 4.x GDExtension wrapping FluidSynth for MIDI playback:
- ~GDMidiAudioStreamPlayer~ - AudioStreamPlayer subclass for MIDI playback
- ~MidiFileReader~ - Resource class for loading .mid files
- ~SoundFontFileReader~ - Resource class for loading .sf2 soundfont files

*** Architecture

**** Source Files (src/)
| File                     | Purpose                                               |
|--------------------------+-------------------------------------------------------|
| register_types.cpp       | GDExtension entry point, registers all classes        |
| gdmidiplayer.cpp/h       | Main GDMidiAudioStreamPlayer class wrapping FluidSynth|
| midi_file_reader.cpp/h   | Resource loader for MIDI files                        |
| soundfont_file_reader.cpp/h | Resource loader for SoundFont files               |

**** Key Integration Pattern

FluidSynth expects file paths, but Godot resources are in-memory. The extension uses a custom sfloader with memory callbacks (~my_open~, ~my_read~, ~my_seek~, ~my_tell~, ~my_close~) that interpret a pointer address encoded as a string (~"&%p"~) to load soundfonts from Godot's resource system.

**** Build Output
- ~bin/<platform>/~ - Raw build output
- ~gdmidiplayer/bin/<platform>/~ - Copied for Godot project use

****** Analysis

Fluidsynth is not a header-only library. It requires:
1. Headers (~fluidsynth.h~) for compilation
2. Shared library (~libfluidsynth.so~) for linking
3. Runtime library on target system (unless statically linked)

****** Solution: Cross-platform CI with vcpkg

Desktop platforms (Linux, Windows, macOS) use package managers:
- Linux: ~apt install libfluidsynth-dev~
- Windows/macOS: ~vcpkg install fluidsynth~

Mobile and web platforms require building fluidsynth from source (deferred).

Android requires cross-compiling fluidsynth with the Android NDK.

******* Prerequisites

- Android NDK (r21 or later recommended)
- CMake 3.13+
- Fluidsynth source code

******* Build Steps

1. Set up NDK toolchain:
   #+begin_src shell :tangle no
   export ANDROID_NDK=/path/to/android-ndk
   export TOOLCHAIN=$ANDROID_NDK/toolchains/llvm/prebuilt/linux-x86_64
   #+end_src

2. Build fluidsynth for each ABI (arm64-v8a, armeabi-v7a, x86, x86_64):
   #+begin_src shell :tangle no
   # Example for arm64-v8a
   mkdir build-android-arm64 && cd build-android-arm64
   cmake .. \
     -DCMAKE_TOOLCHAIN_FILE=$ANDROID_NDK/build/cmake/android.toolchain.cmake \
     -DANDROID_ABI=arm64-v8a \
     -DANDROID_PLATFORM=android-21 \
     -DBUILD_SHARED_LIBS=OFF \
     -Denable-floats=ON \
     -Denable-threads=ON \
     -Denable-openmp=OFF \
     -Denable-alsa=OFF \
     -Denable-jack=OFF \
     -Denable-pulseaudio=OFF \
     -Denable-pipewire=OFF \
     -Denable-oss=OFF \
     -Denable-readline=OFF
   cmake --build .
   #+end_src

3. Copy static library and headers to a known location for SConstruct.

******* Reference

- [[https://medium.com/swlh/creating-a-fluidsynth-hello-world-app-for-android-5e112454a8eb][Creating a Fluidsynth Hello World App for Android]]
- [[https://github.com/FluidSynth/fluidsynth/wiki/BuildingWithCMake][FluidSynth BuildingWithCMake wiki]]

iOS requires cross-compiling fluidsynth with Xcode toolchain.

******* Prerequisites

- Xcode with command line tools
- CMake 3.13+
- Fluidsynth source code

******* Build Steps

1. Build for arm64 (device) and x86_64 (simulator):
   #+begin_src shell :tangle no
   # Device build (arm64)
   mkdir build-ios-arm64 && cd build-ios-arm64
   cmake .. \
     -G Xcode \
     -DCMAKE_SYSTEM_NAME=iOS \
     -DCMAKE_OSX_ARCHITECTURES=arm64 \
     -DCMAKE_OSX_DEPLOYMENT_TARGET=12.0 \
     -DBUILD_SHARED_LIBS=OFF \
     -Denable-floats=ON \
     -Denable-threads=ON \
     -Denable-coreaudio=OFF \
     -Denable-coremidi=OFF \
     -Denable-framework=OFF
   cmake --build . --config Release

   # Simulator build (x86_64 for Intel Macs, arm64 for Apple Silicon)
   mkdir build-ios-sim && cd build-ios-sim
   cmake .. \
     -G Xcode \
     -DCMAKE_SYSTEM_NAME=iOS \
     -DCMAKE_OSX_SYSROOT=iphonesimulator \
     -DCMAKE_OSX_ARCHITECTURES="x86_64;arm64" \
     -DBUILD_SHARED_LIBS=OFF \
     # ... same options as above
   cmake --build . --config Release
   #+end_src

2. Create xcframework (optional, for easier integration):
   #+begin_src shell :tangle no
   xcodebuild -create-xcframework \
     -library build-ios-arm64/src/Release/libfluidsynth.a \
     -library build-ios-sim/src/Release/libfluidsynth.a \
     -output fluidsynth.xcframework
   #+end_src

******* Notes

- iOS apps cannot use audio drivers; only synthesizer output is usable
- Consider Core Audio integration for actual audio playback in Godot

****** DEFER WebAssembly builds
:PROPERTIES:
:ID:       d4e5f6a7-8901-23de-f012-456789012cde
:END:

WebAssembly requires [[https://github.com/jet2jet/fluidsynth-emscripten][fluidsynth-emscripten]], a fork with Emscripten-specific patches.

******* Prerequisites

- Emscripten SDK (tested with 3.1.10+)
- CMake 3.13+
- fluidsynth-emscripten source (NOT upstream fluidsynth)

******* Build Steps

1. Set up Emscripten:
   #+begin_src shell :tangle no
   source /path/to/emsdk/emsdk_env.sh
   #+end_src

2. Clone the fork:
   #+begin_src shell :tangle no
   git clone https://github.com/jet2jet/fluidsynth-emscripten.git
   cd fluidsynth-emscripten
   #+end_src

3. Build with emcmake:
   #+begin_src shell :tangle no
   mkdir build && cd build
   emcmake cmake .. \
     -DCMAKE_BUILD_TYPE=Release \
     -Denable-oss=OFF \
     -Denable-alsa=OFF \
     -Denable-jack=OFF \
     -Denable-pulseaudio=OFF \
     -Denable-pipewire=OFF \
     -Denable-threads=OFF
   cmake --build .
   #+end_src

4. Output files:
   - ~build/src/libfluidsynth-<version>.js~ - JavaScript glue
   - ~build/src/libfluidsynth-<version>.wasm~ - WebAssembly binary

******* Integration Notes

- The Emscripten build outputs a JS+WASM pair, not a static library
- For GDExtension web builds, fluidsynth would need to be compiled into
  the extension itself, requiring significant SConstruct changes
- Consider using [[https://www.npmjs.com/package/@nicebyte/js-synthesizer][js-synthesizer]] as a higher-level wrapper

******* Limitations

- Not all FluidSynth APIs work in browser context
- Audio output requires Web Audio API integration
- Threading support is limited (SharedArrayBuffer restrictions)

******* Reference

- [[https://github.com/jet2jet/fluidsynth-emscripten][jet2jet/fluidsynth-emscripten]] - maintained fork
- [[https://www.npmjs.com/package/@nicebyte/js-synthesizer][js-synthesizer]] - high-level wrapper for browser use
